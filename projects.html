AbuseIPDB 기반 Apache 자동 차단

문제

악성 IP의 반복 접근을 수동으로 deny 목록에 넣고 재기동해야 했습니다.

조치

AbuseIPDB API로 블랙리스트를 받아 Apache 2.2(Deny) / 2.4(Require) 규칙 파일을 만들고 crontab으로 갱신했습니다.

결과

2.2·2.4가 섞인 환경에서도 같은 주기로 차단 목록을 유지할 수 있게 되었습니다.

Linux 서버 장애 감지 및 알림

문제

프로세스·포트 다운이나 리소스 이상을 사람이 로그를 보기 전까지 알기 어려웠습니다.

조치

top, ps, df, uptime과 프로세스·포트·저널 로그를 점검하는 스크립트를 만들고 Slack·SMS로 보냈습니다.

결과

야간·무인 시간대에도 이상 징후를 바로 받아 장애 인지 지연을 줄였습니다.

ModSecurity WAF 차단 페이지

문제

ModSecurity 차단 시 기본 403 페이지만 나와 사유를 알 수 없고, 정상 사용자의 해제 요청 방법이 없었습니다.

조치

커스텀 block.php를 만들어 환경변수·audit 로그를 파싱하고, 한글 사유 표시와 해제 요청 폼을 추가했습니다.

결과

차단 원인과 룰 ID를 즉시 확인하고, 사용자가 직접 해제 요청을 남길 수 있게 되었습니다.

SSL 리버스 프록시 구성

문제

웹 서버마다 인증서를 관리하면 만료 추적과 SSL 설정이 흩어졌습니다.

조치

Nginx/Apache에서 SSL을 종료하고 백엔드는 HTTP로 넘기는 프록시를 구성했습니다. HTTP는 HTTPS로 리다이렉트했습니다.

결과

인증서 관리 지점을 프록시로 모으고 백엔드 웹 서버 설정을 단순화했습니다.

SSSD + LDAP/AD + RADIUS 중앙 인증

문제

서버마다 로컬 계정을 만들면 UID/GID와 비밀번호 정책이 어긋났습니다.

조치

LDAP/AD는 계정 속성, RADIUS는 비밀번호 검증을 맡기고, 서버는 SSSD와 PAM으로 연동했습니다.

결과

SSH 로그인을 중앙 계정으로 맞춰 서버별 계정 생성과 권한 불일치를 줄였습니다.
